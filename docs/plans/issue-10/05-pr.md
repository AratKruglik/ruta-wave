# PR summary: issue #10 (backlog 2.3)

PR: https://github.com/AratKruglik/yt-music-mac/pull/55 (base `develop`, head `feature/issue-10`)

## Summary

Adds the read side of the entity pages, the library, the sidebar playlist list, history and the player page to the `InnerTube` package (backlog row 2.3). It covers typed parsers and client fetches for album, artist (including "Show all"), playlist (paged, with a typed "not available" outcome), the five library sections plus Liked music, the `guide`-based sidebar list with a library fallback, history grouped by day with per-row removal tokens, `next` (Up next queue, radio chips, "Playing from", lyrics and related ids, audio/video counterpart) and the Lyrics and Related pages. The screens that consume these models (backlog 4.1, 4.4, 4.5, 4.8) are not part of this PR; there are no `App/` changes. Requested in #10.

Branch note: the issue text names `feature/innertube-entities`; this run used `feature/issue-10`.

## Security

- OWASP review: 0 Critical, 0 High, 0 Medium. Four Low and four Info findings are recorded as out of scope for this PR.
- Notable concerns reviewed:
  - Request routing: all 11 new methods go through the existing `fetch` / `fetchBrowse` path. Guest calls carry no cookies or `Authorization`. Server-controlled values only become JSON string values on fixed endpoints.
  - Fixtures: no visitor IDs, cookies, emails, account keys or real tokens. Real captures hold only artist-owned or YouTube Music-owned playlists. Lyric text is placeholders. The `related.json` cards of private individuals were removed.
  - Logging: only renderer key names, never titles, tokens or lyrics.
- Open Low findings (follow-up before the first real signed-in capture replaces a synthetic fixture):
  - L1: the scrubber and guard do not mask a private owner in the `facepile` shape.
  - L2: `--mask-id` misses base64 copies of IDs in `params` fields.
  - L3: token scrubbing and the guard match only three key names.
  - L4: continuation tokens are not bound to an identity (`libraryContinuation`, `watchNextContinuation`, `PlaylistPage.sectionsContinuation`).
