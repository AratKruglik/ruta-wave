## Open issues and gaps
- The no-argument `remove()` is untested by design. It would touch the real ~/Library, Keychain and UserDefaults.
- The legacy Keychain identity (`dev.kruhlyk.tunewave.session`, account `default`) is not asserted. The spy ignores the service, and the no-argument form builds it inline.
- Partial failure of a single path (one removal failing while others succeed) is not tested. It can't be simulated without source changes. Per-path `try?` makes the risk low.
- QA ran `swift test` only in Packages/Auth. The other 5 packages and `xcodebuild` were not run, so AC-14 is not fully verified.
- AC-13 (the `git grep` check) was not run by QA.
